# 提示词辅助与 Fast 加速

提供提示词增强、下一问建议和 OpenAI / xAI Priority 加速，增强与建议各自的辅助模型、推理档位、Fast 和 QA 轮数在当前 profile 全局共用。

这是 DeepSeek Harness（DSH）Web GUI 插件包。增强与建议是两项独立功能，可分别启用，也可同时启用，并对当前 DSH profile 的所有普通会话生效。设置位于左侧栏页面，不是输入框弹窗。两项功能的开关与辅助参数均在当前 profile 全局生效，不同会话仍保留各自的问答内容。

> **v1.2.29：** 修复两处交互。设置页草稿反馈不再溢出卡片的 `span 4` 子网格——该溢出曾吞掉完整问答轮数下拉与保存按钮的全部点击，并使必须完成的一次全局保存无法进行，输入框「增强提示词」按钮因此一直保持灰色；推理强度滑块在「减弱动态效果」下恢复最高档闪烁而非静态染色（按上游语义改用 0.01ms 时长压缩）。无网络、存储或模型调用变化。[详见变更记录](<CHANGELOG.md>)。
> **v1.2.28：** 原输入框模型选择器改为供应商分组：标题下直接列出各自模型，沿用 Claude Style 0.16.3 内置说明，推理强度改为带刻度的离散滑块。不增加并列入口，没有自定义说明卡片，也不新增 profile 存储。[设计与来源](<docs/model-picker.md>)。维护者发布不会自动安装或升级当前 profile。

> **v1.2.27：** 增强／建议结果框直接随原生输入框定位，修复 Claude Style 新会话工作台中的大段间隔；高度适配可用空间与缩放，原生菜单优先。不修改主题安装文件、模型调用策略或已保存全局设置。**若从 v1.2.25 及更早版本升级，请为使用中的功能各保存一次全局配置；v1.2.26 已确认的配置无需重存。**

## 兼容策略

版本声明使用 `engines.dsh: >=0.2.1-rc.1`，允许后续 RC、补丁、次版本与主版本尝试加载，不代表所有未来版本都已测试。插件挂载前检查所需 Host 能力，Fast 接入点保留严格接口检查；缺失能力会在报错中明确列出。CI 同时检查版本放行规则及两个当前核验版本的真实适配器契约。

## 环境要求

- **最低支持 DSH `0.2.1-rc.1`，不设置未来版本上限。** 启用前检查必要 Host 接口及 Fast 适配器接入点，而不是按次版本号拦截。当前核验目标为 `0.2.1-rc.1` 与 `0.2.1-rc.2`；新版本号本身不导致拒绝，但真实接口变化仍可能需要适配。不使用版本豁免。
- 已在 DSH 中配置服务商和模型；插件不提供 API 凭证。
- 安装时能够访问 GitHub，生成时能够访问所选服务商。
- **Node.js 22+ 与 pnpm 仅供开发。** 分发版本包含预构建产物，普通安装无需自行构建。

## 从 GitHub 安装

在 DSH 的 **插件** 页面选择安装，填写：

```text
github:Syngnat/dsh-prompt-assist
```

如果当前环境提供并授权使用插件管理工具，等价调用为：

```js
plugin_manager({
  action: "install_bundle",
  target: "github:Syngnat/dsh-prompt-assist"
})
```

不需要填写版本号。DSH 安装的是仓库默认分支，并非自动解析 GitHub 最新 Release。本仓库通过发布流程确保 `main` 只保留已验证的最新稳定版和预构建文件；开发与候选版本在其他分支。已安装的插件不会自动跟随新提交。

不要填写 GitHub `/tree/` 页面地址或裸 `Syngnat/dsh-prompt-assist`。

请检查安装返回结果：`application: applied` 表示 Host 已激活；`restart-required` 表示需要重启 DSH。依赖下载成功不等于浏览器界面已验收。如果依赖构建脚本被阻止，应先核对返回的包名再决定是否授权，不要全局放行脚本。

为兼容已有本机用户，包名仍为 `@local/dsh-openai-fast`，与仓库名 `dsh-prompt-assist` 不同。`private: true` 用于防止误发 npm，不妨碍 GitHub 安装。

## 使用

### 全局开关、模型与 QA 参数

1. 打开左侧 **提示词辅助**。顶部两个全局开关不要求选择会话，修改即保存到当前 profile；已有和新建会话都沿用，刷新或重启 DSH 后仍保留。不同 profile 相互独立。
2. 开启下一问建议，表示允许该 profile 中符合条件的未来新 QA 自动请求。开启、重连或重新打开页面不会追溯旧 QA。全局变更或实时同步断开会使当前辅助预览失效；保存失败不会显示成已保存。
3. **模型、原生推理档、辅助 Fast 和完整 QA 轮数均在当前 profile 全局共用**，不再需要选择会话。增强与下一问建议各有一份配置，已有和新建会话使用同一份已保存值。
4. 修改后保存该功能的全局配置；其他窗口和会话会同步。保存参数不改变两个功能开关。另一个窗口已修改时，保留当前草稿并提示冲突，不会自动覆盖。

**首次升级到 v1.2.26后，请为需要使用的功能保存一次全局配置。** 不同旧会话可能配置不同，因此不会任意选择或自动合并。旧全局开关保留，但在该功能的全局模型配置确认前，不会自动发起建议请求；旧日志留作兼容，不再覆盖全局参数。无需逐个会话重设。

“跟随会话模型”是一个全局保存的策略，每次请求仍解析其所在会话的模型和推理档位，而不是绑定保存设置时的某个会话。QA 轮数全局统一，**QA 内容仍只来自本次调用所在会话**；文件选择和草稿也不会全局共享。主对话自身的模型选择及主 Fast 开关不受这些辅助配置修改影响。

首次全局开关默认关闭；旧会话开关只保留日志兼容性，不覆盖全局设置。从v1.2.11或更早版本首次升级时，请在全局区明确开启一次；之后升级会保留全局开关，无需每个新会话重开。跟随会话只跟随模型与推理档位，辅助 Fast 始终独立。QA 范围可选 1、3、5 轮，或自定义 **1–20 轮完整问答**；无效值会被拒绝，不会静默取整或限幅。切换模型后，如果旧推理档位不受支持，需要主动重选，不会自动降档。

### 模型菜单与模型说明

每个供应商标题下直接列出其模型。说明沿用随包提供的 Claude Style 0.16.3 原始数据，未匹配时回退到宿主模型 metadata；都没有则留空，不编造。说明是上游文案，不是本插件对模型能力的独立评测；没有编辑器、存储或额外模型调用。

列表底部是离散推理滑块，只呈现当前模型实际支持的档位。拖动先预览，释放后提交一次；不支持推理时隐藏，单档时禁用。重新点击当前模型不会重置推理档，切换仍由宿主会话目录和权限控制。

同一模型选择器建议只启用一种替换功能，尚未验证与所有第三方主题同时开启的效果。详见[设计与来源署名](<docs/model-picker.md>)。

### 增强输入原文

在主输入框写好原文，点击增强图标按钮。增强以这段原文为基础优化表达，最近完整 QA 只提供背景，不替换用户任务。**主会话 Busy 时仍可增强**，前提是输入框可编辑且当前会话有权限；增强不会把结果直接发送成聊天消息。

查看输入框上方的结果区，需要时展开原文对照，再选择复制或应用。纯文本应用会核对原文与草稿版本，形成一次可撤销的文本编辑，保留附件。修改草稿会取消过期请求；只有应用后的文本和版本仍匹配时，才提供撤销本次应用。

增强保持用户向助手表达需求的视角，结合已确认上下文，不擅自新增澄清步骤；核心含义无法确定时保守改写或保留原文，不猜测意图。

从 v1.2.26起，明确区分“没有历史 QA”和“原文无法理解”：新会话仍应依据原文本身纠错、去重和分项，局部不确定不能使整段照抄。粘贴需求文档时，只整理有依据的结构，保留规则、样例及例外，不重新求解业务规则、计算样例结果或补写截断内容。这些是编辑规则和离线回归，不代表已实测所有模型的改写质量。

增强规则要求多个独立要点使用真实换行、短段落或列表，并输出完整替换稿，不在原文后堆叠补充。已清晰的短请求不强行扩写。模型若最终原样返回（仅忽略首尾空白与换行编码差异），界面会提示未产生有效改写，并禁止再次应用相同文本；这不是语义质量评分，不会把所有轻微润色都自动判为无效。列表与代码换行原样保留，不使用按标点硬拆行的格式化，也不自动追加付费重试。

### 生成下一问建议

自动建议基于所选最近 N 轮完整 QA。仅在**新的完整问答**出现、会话空闲，且草稿没有文字、引用、附件时自动请求。安装、首次挂载或重新打开界面只建立基线，不追溯旧 QA。工具栏的建议按钮也可在条件满足时，基于已有完整 QA 手动生成。

**主会话 Busy 时不可请求建议。** 输入、配置、模型、会话或 QA 变化使请求过期后，旧结果会被丢弃。已取消的自动尝试不会被静默重复请求，需要时请手动重试。

建议保留用户原有询问和授权边界，不将助手未确认的建议当成用户意愿；没有有依据的下一步时可返回正常的暂无建议。从 v1.2.25 起，自动触发的正常空结果安静结束，不弹出“暂无建议”；手动点击生成仍显示中性提示与忽略，不提供可采用/复制的正文。空结果仍如实保留在内部状态，不计作生成了建议，也不自动重试。

生成策略更贴近用户自然的下一条输入和表达习惯，而不是替用户规划工作。完成声明、多种方向和待授权节点不再直接导致弃答；先寻找与原目标有关、尚未回答的具体问题或明确约定的下一步。不会强行追加验收清单，也不把未确认的执行意愿写成授权。参考本机 Codex 客户端的已验证机制，未获取或复制其服务端提示词；仍严格使用用户配置的 QA 范围。

建议完成协议校验后才展示，增强仍保留流式预览。空响应、格式错误、截断和请求失败仍是错误，不会伪装成暂无建议。

### Fast

**Grok 支持（v1.2.24）：** 识别 `grok-4.6`、`grok-4.7`，并前向识别未来采用同样命名的 `grok-4.8` 和更高主版本。模型识别不保证上游支持 Priority；供应商仍须授权，且使用受支持协议。请求只增加 `service_tier: "priority"`，不改模型 ID、不降低推理档位、不自动重试为普通档。新模型须先在供应商目录中配置或发现，本插件不自动添加模型。xAI 官方 Priority 为标准 token 费率的 2×，DSH 估算不保证反映溢价，以服务商账单为准。未进行真实 xAI 付费请求或实际档位回显验证。

**带前缀的 Grok ID（v1.2.26）：** 补充识别 `安和桥/grok-4.7`、`xai/grok-4.7` 等目录命名空间；v1.2.24/1.2.25 只识别裸 ID，因此这种命名会导致按钮隐藏。仅按最后一个模型段识别家族，发送时保留完整 ID；前缀不等于供应商授权，仍须校验真实 provider ID。

**以路由为单位授权。** Fast 的授权单位是 `(供应商, 模型, 协议, 来源)` 路由，而不是模型名，也不只是供应商。给网关授权后，它下面带前缀的 OpenAI 模型不再隐藏按钮，也不会顺带加速该网关的其他家族模型：每条路由解析为 `ready`、`needs-verification`、`grant-missing`、`rejected`、`api-incompatible` 或 `not-candidate`。只有 `api-incompatible` 与 `not-candidate` 会隐藏控件，其余可操作状态一律可见并各自说明原因。授权可指定供应商、该供应商上的某个家族、或某个确切模型，精确模型优先。详见 [Fast 路由授权](docs/fast-route-authorization.md)，`pnpm run fast:truth-table` 可打印全部用例。

> **从v1.2.13起：** 已识别的 GPT/OpenAI 模型不再因供应商未获准或 Host 投影尚未载入而静默隐藏 Fast；改为禁用并说明原因。元数据读取只进行有界重试，不会请求模型。模型名匹配忽略大小写，供应商 ID 仍精确匹配；兼容 OpenAI 协议不代表支持 Priority，不能自动放开收费授权。

主 **Fast** 图标按钮紧邻模型选择器，只作用于明确允许的 OpenAI 或 Grok 4+ 模型路由，并要求上游服务商支持 Priority。它可能额外收费，不保证一定更快。支持继承的子智能体在没有独立设置时继承父会话偏好。

**自助授权其他供应商（从 v1.2.16 起）。** 默认只授权 `openai`、`openai-codex`、`cpa`。若你的路由用的是其他供应商 ID，可在 **提示词辅助 → Priority 供应商授权** 中显式授权。Host 只会列出**已注册且模型目录中确实存在 OpenAI 系列或 Grok 4+ 模型**的供应商，并在写入时重新校验，因此陈旧或被伪造的客户端请求无法授权其他对象。授权需要单独的风险确认，带单调 revision，最多新增 32 个，且不能撤销包内置的三个 ID。授权只表示你接受该接入点的 Priority 处理与可能费用，不代表该接入点已实现 `service_tier`；实际路由仍要求 OpenAI 系列或 Grok 4+ 模型 + 受支持的 OpenAI 协议。Fast 不可用时按钮仍然可见，并说明是供应商未授权、状态未同步，还是会话无命令权限。

两项辅助功能各有独立 Fast 开关，既不跟随主 Fast，也不相互联动。开启其中一个不会开启其他开关。不支持的路由不能新开辅助 Fast；如果开关原先已选中，仍可取消后保存。

### 文件与引用

- 已有文件引用不会自动读取；明确勾选后，才会把文件内容用于本次增强请求。
- 限制为**每个文件 64 KiB、合计 128 KiB**，即 65,536 / 131,072 字节。超限拒绝，不静默截断。
- 不递归读取文件夹；会话引用、上传图片和上传附件不作为文件内容读取。敏感或不支持的文件可能被拒绝。
- 可见引用名可能作为上下文发送。含结构化引用或命令的草稿仅支持预览/复制，暂不支持结构化应用。

### 预览与计时边界

结果使用输入区域已分配的行内空间，不浮盖编辑器。设置位于独立侧栏页面，需返回对话后编辑草稿。生成完成后才可应用。耗时按秒**向下取整**显示，低于一秒会显示 0 秒；命中缓存时显示的是原生成耗时。

当前**不支持**原生 Ghost、→ 采纳，也不新增 Ctrl+Alt+E 快捷键，请使用明确按钮。辅助请求的输入上下文窗口与输出预算跟随所选供应商模型设置。插件不再固定设置 1024/4096 token，不再对草稿、QA 或生成正文另设字符/字节限额；未配置输出预算时沿用宿主/供应商默认行为。输入预检使用宿主 token 估算，不把 UTF-8 字节当作 token；实际计数、输出上限和共享窗口由原生适配器及供应商最终校验。不会自动截断输入或降低输出预算，也不复制或修改主会话的单次覆盖参数。较大预算可能增加耗时和费用，推理也可能占用预算。120 秒等待上限、明确授权的文件读取安全预算和宿主原生载体资源限制独立保留；超限/截断结果不会作为完整结果应用，不自动重试或调档。

## 检查稳定版更新

在左侧 **提示词辅助** 页面底部使用 **版本与更新** 区域。这是插件级功能，无需先选择会话。

- 打开页面不会联网查新或安装；版本检查读缓存，在线更新区读本地安装及任务状态。只有已接受任务会轮询本地进度，不定时联网查新。
- 点击 **检查更新** 后才查询本仓库的 GitHub 最新发布信息；拒绝草稿和预发布版本，区分有新稳定版、版本相同、本地版本较新以及检查失败。
- 展示当前/最新版本、检查时间、发布页链接、固定安装地址和手动升级步骤；检查失败不会被显示为已是最新版。
- 单次检查最长10秒，限制响应体积，合并并发请求，并有30秒短冷却。结果仅在内存中保留，Host/插件重启后重置。
- 不发送会话、草稿、文件或服务商凭证，也不调用模型。GitHub仍会收到Host的IP及常规HTTP请求头等网络信息。
- **单独检查不会下载或安装更新。** 此功能不会给DSH原生插件管理页新增自动升级能力。

### 确认后在线更新

从 v1.2.11 起，受支持的 GitHub 安装可使用独立的 **准备 → 阅读并勾选风险确认 → 确认更新** 流程。低于 v1.2.11 的安装需先手动升级一次，才有此入口。检查和准备都不会安装，风险确认默认不勾选。

Host 将目标和恢复版本固定到不可变提交，通过公开 DSH Plugin Manager API 与宿主任务执行。操作前请保存草稿、设置并备份 profile。替换影响该 profile 的所有会话，插件界面可能暂时消失；操作不是原子事务，尽力恢复也可能失败，重新加入 bundle 可能改变配置覆盖顺序，部分情况需要重启。任务结束前不要退出 DSH：关闭页面不会取消已接受任务，Host 进程重启则会丢失内存任务记录。

本地目录、其他仓库等不受支持的来源仍使用下方手动路径。详见[设计、恢复边界与验证说明](<docs/confirmed-online-update.md>)。不会自动安装更新。

## 隐私与安全

请求会把草稿、选定的完整 QA 上下文、可见引用名，以及明确授权读取的文件内容发送到 **DSH 中选择的服务商**。请在请求前确认这些内容适合发送。

插件不向开发者服务器上传数据，不新增遥测。DSH 本身和所选服务商可能有各自的日志与留存策略。安装 DSH Host 插件会允许代码以本机用户权限执行，工作区沙箱不是插件代码的安全边界。模型输出不可信，应用前应检查。项目不声称已完成独立安全审计，详情见[安全政策](<SECURITY.md>)。

## 手动升级与移除

1. 按常规备份 DSH profile 和会话数据，先保存草稿和功能设置。
2. 在 **插件** 页面按 manifest 包名 `@local/dsh-openai-fast` 找到已安装包。先移除旧插件依赖，再使用同一个无版本号地址添加；不要删除profile或会话数据。
3. 使用 `github:Syngnat/dsh-prompt-assist` 安装，依据 application / 重启提示完成更新；发布新版不会自动修改现有安装。

已有本机用户的包标识与投影标识保持不变。替换插件依赖不会删除会话记录，也不要求重写已有服务商/source 配置；既有 profile override 仍可能影响启用状态。不支持热重载的 profile 可能需要先停止 DSH 再移除，安装后重新启动。仍建议备份，这不代表承诺未来 DSH 版本兼容。

### 从旧本地目录版本迁移

长期运行的 DSH 可能在同包名由本地目录切换至压缩包/GitHub 源时仍缓存旧目录。若出现指向旧目录的 ENOENT，不要往旧目录补放产物掩盖问题。先移除旧依赖，完全退出并重启 DSH，再安装无版本号的 GitHub 目标。会话记录和功能标识保持不变。

## 开发

使用独立仓库、Node.js 22+ 与 pnpm：

```sh
git clone https://github.com/Syngnat/dsh-prompt-assist.git
cd dsh-prompt-assist
git switch -c feat/my-change
pnpm install --ignore-scripts
node build.mjs
node --test tests/*.test.js
```

构建生成[包清单](<package.json>)声明的版本化 Host 产物与 Client 产物。React 和 Harness Client 模块保持外部依赖。发布 tag 应携带完整预构建文件，不依赖使用者的本地源码布局或安装时构建脚本。

测试采用 Node 内置测试与模拟/离线传输。单测通过不等于视觉验收，也不验证真实模型路由；不要给常规测试加入真实收费模型请求。

维护者请遵守[稳定版发布流程](<RELEASING.md>)，不要把开发或候选改动直接提交到 `main`。

### 输入区布局回归

在独立 DSH Web profile 中打开新会话、关闭引导，并输入无敏感信息的两行草稿（不要发送），使用临时 Playwright CLI 会话执行 `node scripts/test-preview-layout.mjs --session <会话名>`。测试将真实 Preview 组件的合成结果放入原生首屏布局，覆盖五种窗口尺寸和八类状态，检查按钮边界、命中位置、横向溢出及主输入框可达性；不调用模型、不应用文本。结束后恢复视口并移除测试DOM/CSS。仅在隔离测试页运行，不在用户会话运行。报告保存在已忽略的 `output/playwright/`。该浏览器检查不包含在默认离线 Node 测试中。
