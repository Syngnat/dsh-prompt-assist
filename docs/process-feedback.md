# 过程反馈契约（Progress narration）

从 v1.3.0 起，提示词辅助除了「收尾契约」之外，还可以要求模型在长任务中逐轮给出用户可见的进度说明。目标是与 Codex 客户端一致：先一句说明这一步要做什么，再调用工具；工具结果返回后先说一句发现，再继续；最终消息仍只给结论。

## 为什么走 pre-step 提醒

梁神模式的 minimal prompt 只放行白名单内的 system-prompt section，插件注册的 section 与 personaSuffix 都不会到达模型。现有收尾契约因此走 `agent/pre-step`，向已放行的 decision 追加一条 durable 的 user 角色 `<system-reminder>`。过程反馈复用同一通道，不新增模型调用，也不改宿主提示词组装。

## 为什么需要更强的措辞

v1.2.66 的收尾契约里已经有一句「过程与结论分流：执行期间的进度说明压到一句」。同一条路线（`cpa/deepseek-v4.1-flash:1017`）的实测表明这句话不生效：以真实 DSH system prompt 和 3 轮工具结果回放，控制组与当前契约组都是 0 条文字，只有工具调用；把规则改成逐条硬性要求后，3/3 轮都在工具调用前输出了文字。最终提交的文本再回放 3 轮：前两轮工具调用前各一句，第三轮无工具调用，直接给结论。差别在措辞是否具体到「哪一轮、调用前、必须有文字」，而不是语气强弱。

因此 v1.3.0 新增 `PROCESS_FEEDBACK_CONTRACT`，与收尾契约分开组合：

```text
- 过程反馈契约（硬性要求）：
  1. 每次回复中，只要这一轮要调用工具，就必须在调用前先输出一句面向用户的进度说明（约 8–20 个词，使用与用户相同的语言），说明这一步要做什么；禁止只给工具调用而没有文字。
  2. 每个工具结果返回后，先用一句话说明看到了什么或下一步做什么，再发起下一次工具调用；不要连续两次工具调用之间没有文字。
  3. 进度说明只讲下一步动作或刚发现的事实，不预告结论，不写长段落，不列清单。
  4. 不调用工具的最后一轮不要写进度说明，直接给结论、不复述过程；不要用进度说明代替结论。
```

## 开关与注入语义

- 开关名为 `processFeedback`，默认开启，存在独立存储域 `local_prompt_assist_process_feedback_*`。enablement、收尾契约与 controls 的严格记录形状都不变，旧版本仍可读取已知域。
- 设置页「全局功能开关」新增第四个开关「过程反馈」；工具动作 `prompt_assist({action:"set-process-feedback", enabled})` 等价。两者都走各自 revision 的 CAS。
- 包配置 `config.processFeedbackContract === false` 是硬开关，优先于 profile 开关。
- pre-step 只注入当前历史中**尚未收到**的 section：先只开收尾契约、会话中途再开过程反馈时，只追加过程反馈那一段，不重复收尾契约；关掉开关不会撤回已经进入历史的消息，重新打开也不会重复注入已发送过的段。
- 从 v1.5.2 起，**每一轮的第一步重发完整契约**（仍写在同一条 durable user 消息里），同一轮内每 40 个 step 再刷新一次。原因见下节实测：只注入一次时，提醒在长会话里会退到几百条消息之前，模型的进度旁白随之消失。
- `compaction/end` 会清空标记，压缩后按当前两个开关重新注入契约。
- 客户端接受只改变 `finalAnswerRevision` / `processFeedbackRevision` 的实时帧，不再要求 flags 或 controls 的 revision 也增加；同一 revision 下值发生变化仍判为非法帧并断开重连。

## 验证与边界

- 离线测试覆盖契约原文、两段组合、会话中途开启只注入缺失段、关闭不追加、压缩后重注、独立存储域与 CAS、设置页第四个开关、只改提示开关的实时帧。
- 真实模型探针是离线 A/B（同一路由，真实 system prompt，最多 3–4 轮工具结果），不是完整 GUI 视觉验收，也不是统计意义的效果评测。提示词约束不是确定性的：模型仍可能偶尔省略进度句，或在最终消息里混入一句过程说明。
- 注入频率（v1.5.2 实测依据）：Wails 3 会话 `session-82bc26aa`（11 轮、379 step、368 次工具调用）只注入过 2 条提醒（turn 3 与 turn 5 的第一步），turn 6–11 完全没有新提醒；逐轮统计「有工具调用且调用前有文字」的步数只有 turn3 4/12、turn5 2/22，其余为 0。提醒不是没生效，而是太早、太远：模型在第 300 条消息之后不再遵守。因此改为每轮第一步重发 + 同轮每 40 step 刷新，代价是每轮多一条短 durable 消息（约 200 token），而不是每次工具循环都注入。
- 仍是启发式约束，不是确定性保证：模型可能在一轮中途省略进度句，尤其在上下文被压缩或工具结果很长时。
