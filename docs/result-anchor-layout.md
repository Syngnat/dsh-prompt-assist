# 结果框随输入框定位（1.2.27）

## 原因与边界

结果原先挂在 `conversation.input.dock`。原生布局中，这个插槽与输入框在同一纵向容器内；但已安装的 Claude Style 0.16.2 工作台规则将 **所有 dock 内容**设为 `order: 1`，随后把工作区行设为 `order: 2; margin-top: auto`，输入框设为 `order: 3`。因此统计卡与增强结果留在上方，自动留白把工作区行和输入框推到底部。

这是新会话工作台的布局兼容问题，不是把共享模型设置误用到某个会话。源码规则与用户截图相符，且已在隔离布局夹具复现；未取得现场已认证浏览器的计算样式，因此不把夹具测量值当作现场测量值。

## 修复

- 只将本插件结果移至原生 `conversation.input.overlay`。它是输入卡片内部的零高度定位锚点，属于同一个常驻输入框；不替换原生输入框、不移动其他插件 DOM。
- 结果容器相对该锚点定位，底部相距 8 CSS px。正常结果与输入卡同宽，等待及撤销保持紧凑宽度。
- 高度受可视视口和自身祖先滚动容器共同限制，并换算页面缩放；不足以容纳一行可操作控件时隐藏，空间恢复后重新显示。隐藏不会自行取消请求或改动草稿。
- 继承输入框的可见性，避免原生 settling 阶段输入框隐藏而结果单独露出。
- 结果是非模态浮层，可能覆盖后方内容；只有结果本身接收指针。原生斜杠菜单等浮层保持更高层级。没有使用固定屏幕坐标、全局主题覆盖或 DOM 迁移。
- 只在结果可见组件挂载期间监听尺寸和滚动；卸载时清理观察器、监听和待执行帧。会话隔离、生成、应用、取消和撤销仍由原有控制器负责。
