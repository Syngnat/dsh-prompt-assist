# 用户确认的在线更新（v1.2.11）

从 v1.2.11 起提供本功能。旧版本需先手动升级一次才有在线更新入口；发布新版不会自行升级任何现有安装。

## 用户路径

1. 打开提示词辅助页的“版本与更新”，主动检查稳定版本。
2. 有新版且安装方式受支持时，勾选默认未选中的风险确认，点击“检查并安装更新”。一次点击内客户端先请求准备（Host 解析目标和恢复来源、核对不可变提交），准备成功后才提交安装；协议仍是准备与确认两个独立请求，只是界面合并为一个动作。
3. 若准备失败或确认被拒绝，界面停在复核区并显示版本、不可变提交与错误码，可手动重试；不会自动重连或重发。
4. 宿主任务调用原生管理器完成操作。正常路径不要求用户手动卸载、重装，也不自动重启。
5. 插件替换期间页面可能消失。重新打开读取任务结果；如提示重启，完全退出 DSH 后再启动并核对“当前运行版本”。

检查、准备、安装是三个独立阶段（界面把准备与安装合并为一次点击，但两次请求各自独立）。GET 不联网查新、不安装；准备只读公开元数据。只有确认会启动安装。已接受任务的本地状态轮询不是后台自动更新。

## 权限和公开接口

- 精确 Fetch 路由注册在公开 Connection registry，沿用其 owner 认证和 Host/Origin 信任检查；不创建绕过认证的 WebServer 路由。载体可能规范化 Request URL 或省略浏览器自动生成的头，不能用该 URL 重做浏览器 Origin 判断。
- 确认请求要求 JSON、有限体积、精确字段、一次性随机 token、明确的 true consent、相同目标版本及未过期计划。token 不进入工具输出或浏览器持久存储。
- 模型工具只提供 status、check 和只读 operation，没有 prepare/confirm/install 动作。参数不接受任意包名、源地址、脚本批准或版本豁免。
- 安装仅调用公开 pluginManager 的 listBundles、listPlugins、removeBundle、installBundle、setBundleEnabled、cancelInstall。不直接写 profile 文件，不自行执行包管理器来绕过拒绝。
- jobs 注册为不依附会话的 Host 任务。controller 只在同步 start 周围短暂注册，并在 finally 中立即释放；挂载、GET、准备阶段不长期开放全局作业准入。此短窗口仍可能被同步可信事件监听器重入，不能把它描述为严格的按 kind 权限隔离。

## 来源和执行

只支持当前 profile 中已启用、无管理错误的本包，以及固定 GitHub 仓库的无 ref、对应稳定版 tag 或 40 位提交来源。链接目录、任意仓库、开发分支、内置只读安装等拒绝在线处理。

准备将目标和恢复版本固定到提交，并核对该提交的包名、版本与 bundle 元数据。预检会拦截包自身的 preinstall、install、postinstall 和 prepare 钩子；原生管理器的兼容性、构建脚本策略和错误结果仍然有效，不自动批准或豁免。

热重载模式先依法移除旧包，再安装目标且不自动选入，核对身份和版本后启用。无热重载时采用公开管理器允许的覆盖安装路径，并保留重启要求。不是通过更换 tag/SHA 来规避 already-installed。

成功同时要求安装清单匹配、入口 Fiber active，以及通过公开 Connection 的本地 GET 分派读到目标运行版本。该分派不执行网络请求。仅有管理器 applied 回执或磁盘版本变化，不足以宣称新代码已生效。恢复也单独核对原运行版本。

## 失败和连续性

- 更新不是原子事务。失败后用事先固定的旧版来源尝试恢复，恢复也可能失败。
- 恢复来源优先使用已记录的提交；无提交的安装按版本 tag 解析。这不是原安装字节或整个 profile 的快照，不代替备份。
- 重新加入 bundle 可能改变组合顺序及配置覆盖优先级。配置和会话数据不由此插件删除，但不能保证所有有效配置或未来版本行为完全不变。
- 每一步都核对当前安装。若出现不同的并发安装，恢复拒绝覆盖它；本插件的串行控制不锁住其他独立管理器调用者。
- 关闭页面或卸载生产者不会取消已接受的 Host 任务。取消请求不等于已取消；已发生变化时仍需完成恢复处理。
- 安装与恢复均失败时，本插件页面可能不存在。原生 jobs 仍保留失败状态，不能把手动修复指南当成在线更新成功。
- Host 进程重启会丢失内存任务记录。浏览器只保存版本和任务 id 的非授权标记；结果不明时不自动重发 POST。明确提交前拒绝可重新准备；真正记录丢失须成功重读并人工核对后才能清除本地标记。
- 日志快照和工具输出只保留十个协议字段；无效或异常结束记录降级为 unknown，不透出任意历史字段。

## 验证入口

- [Host 与状态机测试](<../tests/online-update-host.test.js>)：授权载荷、过期/重放、并发、来源、安装/启用/移除/恢复失败、取消、运行版本和重启、快照白名单、controller 租约。
- [客户端测试](<../tests/online-update-client.test.js>)：明确确认、断线、不重发、默认未选复选框、轮询、记录丢失和本地标记清理。
- [真实 jobs 契约脚本](<../scripts/check-online-update-jobs.mjs>)：独立 Context 验证生产者/controller 卸载、非消费读取、取消和根关闭清理；已加入 [SDK CI 矩阵](<../.github/workflows/ci.yml>)。

离线测试不等于真实生命周期验收。本次另在 Windows、DSH 0.2.1-rc.2、Chrome 中使用仓库外临时 DSH_HOME 和打包的两个本地 fixture，验证真实管理器和 jobs：成功后运行版本切到目标；安装失败后自动恢复；恢复也失败则无安装并明确报告需修复。已保存的 QA=5 设置在成功和恢复路径保留。

fixture 仅替换版本元数据和下载来源，不替换管理器或 jobs；模拟版本不代表发布了新版本。没有从 GitHub 下载未发布的候选包，没有执行生成模型质量评测，也没有升级当前用户安装。rc.1/rc.2 的真实 jobs 契约均在本地通过，并纳入候选提交的 CI；稳定发布须等待同一提交的全部 CI 通过。

测试目录必须与被测包仓库分离：仓库内嵌套的同名包测试曾出现加载开发源码而非目标 fixture 的解析干扰。最终验收使用独立临时目录，并同时核对已安装版本与实际运行版本。

另已实测确认后立即关闭浏览器页，Host 仍完成安装、启用与目标运行版本验证。匿名请求返回 401；已认证但外部 Origin 的请求返回 403。无 HMR 覆盖安装及需重启分支已做离线回归，未在关闭 HMR 的真实 Host 上单独验收。

模型工具输入定义离线 JSON 字符数由 515 变为 499；没有新增写操作工具。这不是整段首轮提示词的 token 实测。重复构建产物字节一致；发布流程要求预构建已提交、产物差异检查通过，并独立核对精确候选提交的远程 CI。
