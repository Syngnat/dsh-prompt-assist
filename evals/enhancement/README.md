# 提示词增强：离线评测工作台

本目录先落实评判标准与对照评测，**不参与插件生成、展示或应用结果的运行路径**。所有命令只读取本地 JSON、计算并输出结果；没有模型客户端、网络调用、付费评测、自动重试或默认校验调用。

## 文件与职责

- [评审规范](<rubric.md>)：原意优先，四类判定及证据要求；供人或未来获准的评审模型阅读。
- [参考样例](<cases.json>)：原文、QA、候选及维护者参考标签。`user-confirmed` 只标记用户明确裁定的具体案例，其余为 `proposed`，仍需人工复核。来源字段和确认状态不是同一概念。
- [本地工具](<cli.mjs>)：校验样例、导出不带答案的评审包、生成空记录、比较外部提供的评审结果。
- [比较逻辑](<evaluate.mjs>)：只检查结构、引文出处和声明自洽，不从文本自动推断原意或增强价值。

这是公开的开发对照集，不是独立隐藏测试集，也不代表真实用户请求的统计分布。已有结果样例不证明实际模型表现；合成测试中把参考标签填回去得到一致，只能验证评分程序。

## 操作步骤

在源码工作区使用 Node.js 22 或以上版本：

```powershell
node evals/enhancement/cli.mjs validate
node evals/enhancement/cli.mjs export > .release-check/enhancement-blind.json
node evals/enhancement/cli.mjs template > .release-check/enhancement-judgments.json
# 人工填写 judgments 文件后：
node evals/enhancement/cli.mjs score .release-check/enhancement-judgments.json
```

也可通过 `pnpm run eval:enhancement <命令>` 使用。评测目录不在插件运行发行文件中；这些命令用于源码仓库，不要求安装或升级 profile。

1. 先运行 `validate`。通过只说明字段、标签声明关系和引文位置合规，不是确认所有参考标签正确。
2. 评审时提供规范和 `export` 结果。不要同时提供原始参考样例或带答案的报告。导出只包含原文、QA、候选、无语义标签的 ID 和版本指纹，不带参考标签、依据、分组或确认状态；顺序会确定性打散。
3. 填写 `template`，保留 `datasetHash`。空模板故意不能评分，不会把未填写的答案当成“无法判断”。`evaluator.kind/name` 是提交者声明，工具不验证真实身份或调用来源。
4. 每条记录须填写四类标签、原意和收益判断、原文问题、具体改动、理由及引文。引文必须能在指定位置找到；至少引用候选和原文或用户 QA。助手回复可作为“未确认建议”的证据，但不能单独充当用户授权。
5. 运行 `score`。未知 ID、重复、缺题、错误版本、无法定位的引文和声明自相矛盾会拒绝评分，而不是删除失败样本后报高分。
6. 人工复核争议和关键通过项。真实引文可能被曲解；正确标签也可能配有错误理由。报告始终保留 `semanticVerification: false` 和 `humanReviewRequired: true`。

所有文件写入由使用者显式重定向决定。工具本身不修改原始样例、结果文件、profile 或用户草稿。修改判定规范需更新规范版本；修改样例、上下文、参考标签或确认状态会改变指纹，旧结果不会被默默拿来比较。

## 标签与声明一致性

| 原意声明 | 收益声明 | 可提交标签 |
|---|---|---|
| changed | 任意 | drift／偏离原意 |
| uncertain | 任意 | uncertain／无法判断 |
| preserved | specific | effective／有效增强 |
| preserved | cosmetic 或 none | cosmetic／仅润色或无明显增强收益 |
| preserved | uncertain | uncertain／无法判断 |

这张表只校验评审者自己的声明是否自洽。它不意味着只要模型声称 `preserved + specific`，质量就通过；该声称仍可能被参考标签和人工复核否定。

## 必须同时看的指标

- **参考标签一致率**及四类混淆矩阵，不称为已证明的真实质量准确率。
- **无效放行**：参考为仅润色、偏离原意或无法判断，却被评为有效增强；报告数量、分母和具体 ID。
- **有效改善漏判**：有价值的小纠错或结构改进被否定；不能用“全部判无法判断”换取表面上零误放行。
- 各参考类别与确认状态的分开统计。用户确认案例很少，不可把其结果外推为普遍能力。
- 争议理由的人工审查。程序只保证引用能定位，不能保证引用支持结论。

将来比较同模型校验、不同模型校验或不同提示词时，应使用相同原文、QA、候选、规范和完整样例，不只挑成功案例。对照组中的上下文变体应一起看；若建立训练/留出集合，应按 `group` 分组，避免相同原文和候选跨集合泄漏。当前没有宣称建立过独立留出集。

**只有后续经授权的实际评测表明确实减少误放行、没有不可接受的漏判且成本可接受，才讨论是否接入运行时。当前不作该决定。**
